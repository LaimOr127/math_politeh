# Проверка безопасности учебного сайта

12 ноября 2026 года. Область: vanilla JavaScript в site/teacher, встроенный HTTP-сервер Node.js, защита учебных файлов и наблюдаемая публичная поставка. Использован javascript-general-web-frontend-security.md навыка Security Best Practices. Отдельного справочника для встроенного HTTP Node.js в навыке нет; Express к проекту не применяется.

Локальная версия ограничивает доступ к файлам серверной сессией, проверяет Origin/JSON, ограничивает тело и попытки входа, не хранит коды в Web Storage, экранирует вывод учебных данных и сохраняет строгую CSP. Два подтверждённых дефекта обработки входа исправлены с регрессионными тестами. Публичный сервер пока содержит прежнюю статическую версию, поэтому локальные гарантии на него не распространяются.

## Нерешённые вопросы размещения

### SEC-01 — средняя серьёзность, приоритет P1: прямое скачивание обходит требуемый вход

Место: текущая поставка на 83.217.202.54:8080, путь `/lessons/output/new-learning-guide.docx`. Браузер без сессии получил 200; API сессии и /health вернули 404. Интерфейс показывает старого Пытика. Прямой URL позволяет получить учебные материалы без кода преподавателя.

Исправление: развернуть текущий Node-сервер и направлять через него все маршруты. Локальный `server/app.js` уже возвращает 401 до входа и после выхода; проверено для всех 18 опубликованных файлов. После выпуска обязательно повторить проверку на публичном адресе. Доступа к VPS в текущей сессии нет; проблему нельзя объявить исправленной одним push.

### SEC-02 — средняя серьёзность: опубликованный адрес использует HTTP

Указанный владельцем адрес открывается по HTTP. При вводе кода на таком адресе сеть может перехватить код и cookie. Не проверено, существует ли отдельный HTTPS-домен этого проекта.

Для публикации кабинета использовать HTTPS-прокси, PUBLIC_ORIGIN с точным HTTPS-origin и COOKIE_SECURE=true. Эта конфигурация покрыта интеграционным тестом: иной Origin и text/plain отклоняются, успешная cookie имеет Secure, HttpOnly и SameSite=Strict.

## Исправлено в исходниках

- SEC-03, низкая серьёзность: JSON null вызывал исключение и 500. Теперь допускается только JSON-объект с текстовым code; неверные структуры дают 400 без cookie. Тест включает null, массив, число, boolean, строку, отсутствующий/числовой code и повреждённый JSON.
- SEC-04, низкая серьёзность: покусочное преобразование Buffer в строку повреждало кириллический код. Теперь ограничивается число байтов, а декодирование выполняется после получения тела. Тест реально разделяет UTF-8-символ между HTTP-фрагментами; отдельно проверены 413 и работоспособность сервера после превышения лимита.

## Границы и проверка

`npm.cmd run check` — 20/20. Серверные тесты также проверяют прямые ссылки, неизвестные/старые файлы, обход путей, чужой Origin, лимит попыток, истечение и отзыв сессий, защитные заголовки и MIME локальных ресурсов. Браузерная проверка подтверждает вход, 18 разрешённых скачиваний, восстановление сессии и 401 после выхода.

Слово lesson намеренно сохранено по требованию владельца (ADR 0002). Оно даёт общий доступ к учебным материалам, не подтверждает личность преподавателя и не подходит для персональных данных или административных действий. Код можно заменить переменной TEACHER_CODES. Сессии рассчитаны на один процесс; общее хранилище при нескольких репликах остаётся существующим архитектурным ограничением.

Новых зависимостей, внешних исполняемых скриптов, расширений CSP или секретов в клиенте не добавлено. Это целевая проверка приложения, без проникновения на VPS, нагрузочного теста и аудита конфигурации неизвестного прокси.
