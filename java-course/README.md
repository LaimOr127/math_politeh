# Орбита Java

Если вы открыли ZIP: документы находятся в materials/, Java-примеры — в examples/, итоговое приложение — в project/. Для его запуска начните с project/README.md. Сайт, общий JSON и генераторы доступны в полном Git-репозитории; раздел сборки ниже относится к нему.

Курс для 10–11 классов: 10 занятий по 90 минут, каждое делится на 45 + 45 минут после слайда 7. Короткая база Java переходит в задачи логики, обработки данных и графов. Финал — локальный маршрутный центр с веб-интерфейсом.

| Занятие | Тема |
|---|---|
| 1 | JDK, компиляция, типы, арифметика и ввод |
| 2 | Логика, таблицы истинности и контрпример |
| 3 | Циклы и системы счисления |
| 4 | Массивы, пары и сложность |
| 5 | Строки и инвариант суффикса |
| 6 | Рекурсия, динамика и подсчёт путей |
| 7 | Графы и поиск в ширину |
| 8 | Оптимальный путь и число путей на DAG |
| 9 | Методы, контракты, файлы и тестирование |
| 10 | Java HTTP приложение и защита проекта |

## Что готово

- Сайт: http://localhost:8080/site/java/ после запуска npm start из корня репозитория.
- output: 10 PPTX по 15 слайдов, 10 сценариев Word, общее научно-методическое пособие и архив со всеми материалами и исходниками.
- examples: 10 основных Main.java и 2 дополнительных примера ввода/чтения файла.
- project: полное работающее Java-приложение, инструкция и тесты.
- content/course.json: единый источник сайта, слайдов, сценариев и учебного содержания.

Защищённые скачивания доступны из /teacher/ по серверному коду преподавателя (по умолчанию lesson). Общий код не является личной учётной записью. Сайт самопроверки не исполняет Java и не отправляет код учащихся на сервер. Код выполняется локально на JDK 21.

Примеры связаны с выбранными темами ЕГЭ по спецификации ФИПИ 2027, проверенной 12.11.2026. В ней Java указан среди языков, а задание 23 относится к анализу графов. Курс не покрывает все темы экзамена; установленную среду уточняют в школе. Задачи авторские. Эффективность методики экспериментально не измерялась.

## Сборка и проверка

1. Из корня: npm run sync:java. Команда обновляет модуль сайта и исходники примеров.
2. npm run check проверяет оба курса, Office, компиляцию Java и контракты HTTP. Нужны Node 22+, Python 3 и JDK 21+. Перед проверкой остановите учебный Java сервер на 8090 через Ctrl+C: этот порт используется HTTP-тестом.
3. Для авторства Office используйте внешний Codex runtime, как в lessons/scripts/README.md. Задайте RUNTIME_PYTHON, RUNTIME_NODE_MODULES и PRESENTATIONS_SKILL_DIR.
4. Запустите build_figures.py, build_documents.py и build_presentations.mjs в java-course/scripts. Презентации проходят финализатор и отрисовку; Word требует внешних python-docx, LibreOffice и Poppler из указанной среды.
5. render_documents.py с DOCUMENTS_SKILL_DIR отрисовывает все Word-файлы. Проверьте PNG. Для финального пособия материализуйте содержание через lessons/scripts/update_scientific_contents.py с --docx и --entries .build/java-review/toc-entries.json, отрисуйте повторно и выполните --check по финальному PDF.
6. Только после проверки: python java-course/scripts/package_materials.py. Архив и MATERIALS_MANIFEST.json должны соответствовать финальным файлам.
7. Необязательная браузерная проверка: RUNTIME_NODE_MODULES указывает на внешний Playwright, BASE_URL — на запущенный сервер. Выполните node java-course/scripts/browser_check.cjs. Браузер устанавливается отдельно в среду инструментов, в зависимости сайта он не входит.

Иллюстрации build_figures.py являются авторскими схемами. График показывает теоретическое число операций, а не измеренную производительность. project-screen.png — настоящий снимок поставляемого приложения при w=1. Для обновления снимка запустите проект и снимите страницу локального сервера при тех же данных.

Пособие оформлено с применением ГОСТ 7.32–2017 и ГОСТ Р 7.0.100–2018: A4, поля 30/15/20/20 мм, основной текст Times New Roman 14 пт, интервал 1,5, абзац 1,25 см; код и таблицы используют отдельный читаемый кегль. Реквизиты учреждения/автора не выдумываются; местный нормоконтроль выполняется отдельно.

Публикация в Git не разворачивает сайт на VPS автоматически. Поставку сервера выполнять через Node или Dockerfile, не через статический сервер всего репозитория.
