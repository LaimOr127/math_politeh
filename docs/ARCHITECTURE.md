# Архитектура учебного комплекса

## Границы

Один сервер Node.js раздаёт публичный интерфейс `/site/`, форму `/teacher/` и защищённые файлы. База данных и аккаунты учащихся не используются. Прогресс, тема и отметка знакомства хранятся в браузере. Python исполняется локально в VS Code, сервер код ученика не принимает.

## Слои

```text
lessons/content/lesson-XX.json
  ├── sync_site.mjs → site/src/data/course.js
  ├── create_presentations.mjs → PPTX
  └── build_documents.py → DOCX

build_illustrations.py → lessons/illustrations → сводный DOCX
отрисовка DOCX → update_scientific_contents.py → содержание с реальными страницами

course.js → domain/Mission.js → ui/app.js
                   └────────── storage/ProgressStore.js
                                  ├── ProgressStore
                                  └── PreferencesStore

teacher/app.js → /api/teacher/* → server/app.js → lessons/output
```

`Mission` проверяет упражнения и порядок открытия. `ProgressStore` валидирует прогресс и мигрирует старые завершённые уроки. `PreferencesStore` независимо сохраняет тему и отметку знакомства. Только `ProgressStore.js` обращается к localStorage. `ui/theme.js` применяет тему обеих страниц.

## Сервер

`createApp(options)` создаёт незапущенный HTTP-сервер для интеграционных тестов. `server/index.js` читает окружение и запускает его на порту 8080. Используются только встроенные модули Node.js.

После проверки кода выдаётся непрозрачная cookie-сессия. Доступ проверяется при запросе каталога и каждого файла. Выдача ограничена перечнем финальных имён. Источники, серверные файлы, Git и кандидаты не раздаются. POST проверяется по Origin и JSON. Ограничиваются частота попыток, размер тела и время запроса. Сессии и счётчики удаляются по истечении срока.

Настройки: TEACHER_CODES, PORT, HOST, PUBLIC_ORIGIN, COOKIE_SECURE. По умолчанию действует общий код lesson по запросу владельца. Подробности в ADR 0002 и API.

## Поставка

Docker запускает один процесс Node.js от пользователя node. Содержимое копируется при сборке. `.dockerignore` включает server, site, teacher, package.json и материалы. Старый Nginx не участвует в поставке. Без Docker используется `npm start`; статическая раздача репозитория обходит контроль материалов и не поддерживается.

## Содержание и совместимость

Идентификаторы миссий и прежних проверочных вопросов сохранены, поэтому заработанные детали и частичные ответы не теряются. Дополнительная секция сайта показывает общий основной пример. `npm run check` обнаруживает устаревший course.js. Старые missions.js и visuals.js не используются интерфейсом.

Текущая версия рассчитана на один процесс. Нескольким репликам потребуется общее хранилище сессий и ограничений входа. Сервер не собирает учебную аналитику. Клиентские ответы предназначены для самопроверки.

## Оформление и персонажи

Интерфейс использует исходные знак Генезис-X и изображение Искры с сайта-образца, а также локальные Onest/Unbounded. Источники, контрольные суммы и лицензии шрифтов перечислены в `site/assets/SOURCES.md`. Во время работы внешние CDN не нужны; CSP сохраняет self для изображений, шрифтов и скриптов. WebP выдаётся с image/webp.

Искра — проводник интерфейса. Пытик — собираемый учебный робот из канонических историй. Эта граница объясняется при знакомстве; идентификаторы, программы, ответы и печатные материалы не меняются. Светлая и тёмная темы используют общие компоненты; светлый сиреневый первый экран сохранён в обеих темах по образцу цифровой школы.

Проверка размещённого экземпляра до обновления 12.11.2026 выявила старую статическую раздачу без API и с открытым Word-файлом. В тот же день в `/opt/python-course` развёрнут текущий Node-сервер; внешняя приёмка подтвердила API и защиту материалов. Один контейнер обслуживает оба курса; соседние проекты не менялись. Точная версия, резервная копия и порядок обновления — `DEPLOYMENT.md`. HTTP-адрес остаётся прежним; HTTPS для него не настраивался.

## Самостоятельный курс Java

ADR 0003 добавляет java-course/content/course.json → sync.mjs → site/java/course.js и examples. Сайт содержит ученическую часть; полные тексты 150 этапов преподавателя не отправляются в публичном модуле. Те же данные используют build_presentations.mjs и build_documents.py. Десять PPTX, десять сценариев и единое пособие публикуются только через существующий защищённый сервер. Материалы Python сохраняют прежние поля API, пути и прогресс.

Интерфейс Java использует безопасные DOM API, чистые расчёты графа и общий ProgressStore с отдельным ключом. Новых зависимостей времени выполнения нет. Веб-сайт не компилирует Java, не принимает программы и не отправляет данные школьников во внешние AI сервисы. Итоговый Java сервер — отдельный локальный учебный проект, не процесс основного сервера.

Проверки npm run check дополнены сверкой Java Office и компиляцией 12 программ, сравнением DAG с перебором и HTTP контрактом локального проекта. Браузерные проверки используют отдельную среду Playwright, не зависимости сайта. Формулы графика сложности вычислены, педагогические результаты не выдумываются.

## Независимые точки входа на одном origin

ADR 0004 задаёт `/python/` и `/java/` с кабинетами `/python/teacher/` и `/java/teacher/`. Сервер отображает эти пути на существующие файлы без копирования приложений. Внутренние ресурсы и ProgressStore остаются общими; данные уроков, ключи прогресса и навигация независимы. Между курсами нет ссылок. Это два независимых входа в одном процессе, а не два отдельных серверных сервиса.

Кабинет определяет курс только по известному пути и запрашивает `/api/teacher/materials?course=python|java`. Сервер возвращает единый формат `{course,title,lessons,guides}` только выбранного курса. Общие сессия преподавателя и правила защиты файлов сохраняются. Отбор каталога не является новой границей авторизации: действующая сессия имеет прежний доступ к разрешённым материалам. Старые `/site/`, `/site/java/`, `/teacher/` и полный API каталога сохраняют совместимость.
